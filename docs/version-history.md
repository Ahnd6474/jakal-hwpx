# 저장 버전 기록과 복원

문서를 연 뒤 **보기 및 도구 → 버전 기록**에서 사용합니다. 상단 도구 줄은 추가하지 않습니다.

- 원본, 텍스트 수정, 문서 편집, 이전 버전 복원의 저장 시점과 버전 번호를 표시합니다.
- 선택한 버전과 현재 서버 저장본의 본문·표 내용을 비교합니다. 변경 내용에서 검색하거나 업로드 원본과 바로 비교할 수 있습니다.
- 문단 삽입으로 뒤의 모든 문단이 바뀐 것처럼 표시하지 않도록 공통 내용으로 비교 위치를 맞춥니다. 반복되는 내용의 구분이 모호하면 하나의 변경 구간으로 표시합니다.
- 표는 텍스트뿐 아니라 행·열 수와 병합 구조도 비교합니다. 글꼴·그림·쪽 배치 변경은 텍스트 비교에 표시하지 않습니다.
- **이 버전 복원 → 새 버전으로 복원**은 선택한 파일 전체를 새 버전 번호로 저장합니다. 현재 버전과 이전 파일을 덮어쓰지 않습니다.
- 복원 시 현재 고급 설정의 보호 문구·엄격 검증, 문서 구조·참조를 다시 검사합니다. 복원 성공 후에도 다운로드 전에 새 버전의 검증이 필요합니다.
- 미저장 편집이 있으면 기록 열기와 비교는 가능하지만 복원은 먼저 저장한 뒤 진행합니다. 다른 탭에서 저장한 새 버전이 있으면 복원을 차단합니다.
- 모바일은 저장 버전 목록을 가로로 넘기고 변경 내용은 세로로 비교합니다. 복원 버튼은 비교 내용과 별도로 화면 아래에 둡니다.

HWP에서 변환한 문서는 변환 직후의 HWPX가 버전 1입니다. 업로드한 HWP 원본은 기존의 원본 다운로드로 따로 받을 수 있습니다. 변환 정보는 복원 후에도 유지됩니다. 기존 HWP 원본 형식의 저장 문서도 서버에서 복원할 수 있습니다.

## 데이터와 API

`revisions` 테이블이 문서·버전별 저장 시각·작업 종류·복원 기준 버전을 기록합니다. 서버 시작 시 기존 문서와 성공한 편집 작업으로부터 기록을 보충하며 기존 파일은 변경하지 않습니다. 실패한 저장은 기록에 추가하지 않고, 검증만 다시 실행해도 새 버전은 만들지 않습니다. 문서 삭제 시 버전 기록도 함께 삭제합니다. 기존 업로드 후 24시간 보관 정책을 유지합니다.

| API | 동작 |
|---|---|
| `GET /api/documents/{id}/revisions` | 최신 순 20개, 다음 페이지의 `next_before` 반환 |
| `GET /api/documents/{id}/revisions?before=N` | N보다 이전 버전 조회 |
| `GET /api/documents/{id}/revisions/{revision}` | 저장한 버전의 비교용 문서 정보 |
| `POST /api/documents/{id}/restorations` | 현재 `revision`과 복원할 `source_revision`으로 복원 작업 등록 |

모든 경로는 세션 소유권과 문서 만료를 확인합니다. 복원 작업은 기존 프로세스·시간·메모리 제한을 사용합니다. 복원이 실패하면 현재 저장 버전과 설정을 유지합니다. 새 버전 공개 시 파일과 스냅샷을 확인하며, 검증 상태는 초기화합니다.

비교 항목은 30개씩 추가 표시하고 최대 500구간을 보여 줍니다. 긴 변경 구간은 양쪽 각각 16,000자까지 표시하며 제한 안내를 함께 표시합니다. 저장 기록은 20개씩 추가로 불러올 수 있습니다. 비교 표시 제한은 복원하는 원문 파일에 영향을 주지 않습니다.

텍스트 수정이나 복원으로 저장 버전이 바뀌면 원문 편집기도 새 파일로 다시 엽니다. 이전 버전이 편집기에 남아 후속 저장에서 최신 내용을 되돌리는 일을 방지합니다.

## 검증

`web_tests/test_revisions.py`는 저장 목록·이전 내용·새 버전 복원·원본 보존·검증 무효화·보호 문구·버전 충돌·소유권·만료·삭제·기존 DB 이관·페이지 이동·손상된 기록·HWP 복원을 검사합니다. `web/tests/revision-comparison.test.mjs`는 문단 삽입·삭제·반복 내용·빈 문단·표 구조·섹션 변경과 표시 한도를 검사합니다.

2026-10-20: 백엔드·줄 배치 회귀 검사 109개와 프런트엔드 검사 56개, 프로덕션 빌드가 통과했습니다. 이후 추가한 HWP 변환 문서의 복원 검사와 Studio 저장 기록 확인도 각각 통과했습니다. 브라우저에서는 테스트 문서의 본문·표 수정, 비교 검색, 미저장 상태 복원 차단, 모바일 화면, 원본을 새 버전으로 복원한 뒤 검증·다운로드까지 확인했습니다. 받은 복원 파일은 업로드 원본과 바이트 단위로 동일했고 재열기 검사도 통과했습니다. 텍스트를 다시 수정·저장한 후 원문 편집기에도 최신 문구가 표시됨을 확인했습니다.
