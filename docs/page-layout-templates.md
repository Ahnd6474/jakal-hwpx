# 쪽 양식·템플릿

본문의 예시 내용 대신 페이지 자체의 형태를 재사용한다. 사이드바의 **쪽 양식·템플릿**, 편집 중에는 **보기 및 도구 → 쪽 양식·템플릿**에서 연다.

지원하는 설정:

- A4·A3·Letter 및 직접 지정한 용지 크기, 가로·세로 방향
- 좌우·위아래 여백과 머리말·꼬리말 여백(mm)
- 균등 너비 1·2·3단, 단 사이 간격, 세로 구분선
- 머리말·꼬리말을 기존 내용·서식 그대로 유지하거나 한 줄 텍스트로 교체·제거
- 기존 쪽 번호 유지, 제거, 아래 가운데·오른쪽 번호
- 현재 문서 전체 구역 또는 특정 구역에 적용, 이 양식으로 빈 새 문서 만들기

기본 양식은 일반 1단, 가운데 구분선이 있는 2단, 머리말·꼬리말, 가로 3단 안내문이다. 설정을 이름과 함께 브라우저에 최대 20개까지 저장할 수 있다. 양식 JSON 파일을 내려받거나 가져오면 다른 브라우저에서도 재사용할 수 있다. 설정만 보관하는 양식에는 본문·표·그림을 담지 않는다. 머리말·꼬리말을 ‘기존 유지’로 보관하면 이후 적용받는 문서의 내용과 서식을 유지하는 규칙으로 작동한다.

## 파일에서 가져오기

**쪽 양식·템플릿 → 양식 파일 가져오기 → 파일 선택 → 양식 추출** 순서로 사용한다. 추출 단계에서는 현재 문서를 변경하지 않는다. 미리보기를 확인한 다음 적용하거나 내 양식으로 보관한다.

| 입력 | 가져오는 내용 | 사용 방식 |
| --- | --- | --- |
| HWPX 한 파일 | 구역별 용지·여백·단·구분선·머리말/꼬리말 일반 텍스트·지원되는 쪽 번호 위치 | 구역을 선택하고 편집 가능한 쪽 설정으로 적용. 본문, 글자 서식, 머리말/꼬리말의 표·로고는 복사하지 않으며 해당 파일에는 안내 표시 |
| PDF 한 파일 | 각 페이지의 원래 용지 크기와 렌더링한 페이지 배경 | 기존 글자·표·그림 전체가 고정 배경. 그 위에 새 본문을 편집 |
| JPG/JPEG/PNG 여러 장 | EXIF 회전을 반영하고 가로/세로 A4에 비율을 유지해 배치한 배경 | 선택 순서가 쪽 순서. 위/아래 이동·파일명 숫자 순 정렬·제외 가능 |
| 쪽 양식 JSON | v1 쪽 설정 또는 v2 배경 페이지 포함 양식 | 다른 브라우저로 양식을 옮기거나 백업에서 복원 |

PDF·이미지의 원본 글자를 개별 편집하는 OCR 기능은 포함하지 않는다. 배경은 JPEG로 변환되므로 PDF의 벡터·검색 가능한 텍스트 속성은 유지되지 않는다. 여러 쪽 전체를 선택하면 각 쪽을 별도 구역으로 가진 새 문서를 만들며, 각 구역에 본문을 더 작성하면 해당 구역의 배경이 반복된다. 현재 문서에는 한 쪽을 골라 전체 또는 특정 구역에 적용할 수 있다. 가져온 배경만 제거하는 기능도 제공한다. 용지·여백을 바꾸면 배경은 비율을 유지해 새 용지에 맞추며, 머리말 텍스트 교체와 별도로 보존한다.

한 번에 파일 합계 20MB, PDF/이미지 최대 10쪽, HWPX 최대 20구역이다. 이미지는 한 장당 2,500만 화소까지 읽으며 PDF는 최대 200dpi·쪽당 800만 화소로 렌더링한다. 결과 배경 합계는 12MB까지 지원한다. 암호화·손상·범위 밖 파일은 오류 메시지를 표시하고 선택 목록을 유지한다.

배경 양식은 IndexedDB에 별도로 보관하며 목록에는 이름·설정 등 메타데이터만 읽는다. 배경 양식 보관 용량은 합계 100MB까지이고, 설정 양식과 합쳐 UI에서 최대 20개를 보관한다. 브라우저 저장 공간을 지우면 양식도 삭제되므로 필요한 양식은 JSON 파일로 내려받는다. v2 JSON의 배경은 다시 가져올 때 서버에서 실제 JPEG인지 재검증하고 재인코딩한다. SVG·외부 URL은 배경으로 받지 않는다.

현재 문서에 미저장 편집이 있으면 안내 문구와 버튼에 표시하고, 이를 원래 문서에 먼저 저장한 뒤 양식을 적용한다. 적용 결과는 `layout` 종류의 새 버전으로 기록하며 기존 검증을 무효화한다. 다운로드할 때 현재 버전을 다시 검증한다. 이전 버전 복원도 기존 기능을 사용한다. 빈 새 문서에는 예제 문항이나 보고서 문단을 추가하지 않는다.

기존 구역 안의 여러 단 설정은 선택한 쪽 양식으로 통일된다. 단 너비에 맞춰 기존 표나 그림 크기를 자동 축소하지 않는다. 구역의 기존 머리말·꼬리말을 직접 입력 방식으로 바꾸면 해당 영역을 새 일반 텍스트로 교체하므로, 로고·표·다른 글자 서식을 보존하려면 ‘기존 내용·서식 유지’를 사용한다. 도구의 작은 페이지는 구조 예시이며 실제 줄바꿈과 페이지 수는 적용 후 편집기에서 확인한다.

## 처리 경로

- `GET /api/documents/{id}/page-layout?revision=N`: 저장 버전의 구역별 쪽 설정 읽기
- `POST /api/documents/{id}/page-layout`: 기존 공통 작업 계층·버전/설정 충돌 검사·중복 요청 방지를 거쳐 처리
- `POST /api/documents/from-page-layout`: 빈 HWPX에 쪽 설정만 적용해 기존 신규 문서 분석 큐에 전달
- `POST /api/page-templates/extract`: HWPX·PDF·이미지 모음·JSON에서 양식과 미리보기 추출. 업로드 임시 디렉터리는 성공/실패 모두 정리
- 배경이 포함된 새 문서 생성은 기존 분석 작업 큐에서 처리. 현재 문서 적용의 `background_pages`는 생략 시 유지, 빈 배열이면 제거, 한 항목이면 교체. 두 개 이상은 422
- `server/template_extract.py`: 최대 2개 동시 추출, 60초·RSS 768MB 제한의 별도 프로세스로 파일 해석
- `server/page_background.py`: JPEG 검증·재인코딩, 본문 뒤 반복 배경 작성과 용지 크기 변경 시 재배치
- `server/page_layout.py`: mm와 HWPUNIT 변환, 페이지 제어 요소만 변경, 본문 텍스트와 본문의 표·그림·수식·OLE 및 첨부 보존 검사
- 기존 전체 편집 저장 검증으로 새로운 XML/첨부 참조 오류와 보호 문구 위반을 거절
- `web/src/page-layout.ts`: 쪽 양식 데이터·입력 검사·브라우저 보관
- `web/src/PageLayoutTemplates.tsx`, `ImportPageTemplate.tsx`: 적용 범위, 쪽 미리보기, 내 양식, 파일 가져오기·JSON 내보내기 UI
- `web/src/page-template-assets.ts`: 배경 파일과 목록을 원자적으로 저장하는 IndexedDB 보관함

구분선은 HWPX의 `hp:colPr/hp:colLine`을 사용한다. 요소 속성 확인에는 [HwpForge의 HWPX 스키마 구현](https://docs.rs/hwpforge-smithy-hwpx/latest/src/hwpforge_smithy_hwpx/schema/section.rs.html)을 참고했다. 실제 번들 렌더러에서 2단·구분선·머리말·꼬리말 표시와 텍스트 편집 후 HWPX 내보내기 보존, 가로 3단 용지 방향을 테스트한다. 배경은 머리말의 독립 그림 문단과 `BEHIND_TEXT`를 사용하며 번들 렌더러에서 쪽 경계·그리기 순서·본문 편집·내보내기·용지/머리말 변경 후 보존을 검사한다. PDF 해석/렌더링은 [pypdfium2](https://pypdfium2.readthedocs.io/en/stable/), 이미지 정규화는 [Pillow](https://pillow.readthedocs.io/en/stable/)를 사용한다. `pip install -e ".[web]"`로 서버 의존성을 설치한다.

외부 MCP나 AI 수정 기능은 포함하지 않는다. 실시간 웹 브라우저의 화면 조작 검증은 현재 접근 제한으로 수행하지 않았다.
