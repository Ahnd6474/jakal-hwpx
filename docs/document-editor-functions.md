# 온라인 문서 편집 기능 보완

2026-10-21. 기존 HWP/HWPX 편집·검증 흐름을 유지하면서 일반 문서 작업을 보완했다. AI 수정과 외부 AI 서비스 전송은 추가하지 않았다.

## 문서 이름과 복사본

- 문서 위쪽의 파일 이름을 클릭하거나 `보기 및 도구 → 이름 변경·복사`를 연다.
- 이름 변경은 목록과 다운로드 이름을 바꾸며 문서 본문 제목, 원본 바이트, 버전 기록, 검증 상태를 유지한다. 원문 편집기의 파일 이름도 동기화하되 문서를 다시 로드하거나 미저장 편집을 저장 완료로 표시하지 않는다.
- 복사본은 현재 저장 버전의 HWPX 바이트를 독립된 문서의 원본으로 가져온다. 작업 메모·보호 문구·엄격 검증 설정을 함께 복사한다. 새 문서는 버전 1부터 시작하며 기존 문서의 이력은 유지한다.
- 미저장 편집이 있으면 버튼에 `현재 문서 저장 후 복사`라고 표시한다. 이 작업은 원래 문서에도 수정 내용을 저장한 다음 복사하므로, 미저장 내용을 원본에 반영하지 않는 별도 저장 기능으로 표시하지 않는다.
- 서버는 소유 세션, 현재 버전, 이전 이름, 진행 중인 작업을 확인한다. 복사는 세션 20개 제한과 원본 삭제·변경을 같은 트랜잭션에서 확인하며 복사 실패 시 새 파일과 DB 등록을 남기지 않는다.

## 원문 편집기의 파일 메뉴 연결

고정 편집기 버전은 임베드 모드에서 파일 관련 메뉴와 인쇄 명령을 기본적으로 숨긴다. 필요한 명령만 다시 등록하고 사이트의 작업 흐름으로 연결했다.

| 편집기 메뉴/단축키 | 사이트 동작 |
| --- | --- |
| 새 문서 | 사이트의 기본 양식 선택 |
| 열기 | 사이트의 HWP/HWPX 업로드 |
| 저장 / Ctrl·Cmd+S | 현재 문서의 새 버전 저장 |
| 다른 이름으로 저장 / Ctrl·Cmd+Shift+S | 이름을 정해 복사본 만들기 |
| HWPX로 저장 | 저장·검증 후 다운로드 |
| 문서 이력 | 사이트의 버전 비교·복원 |
| 인쇄 / PDF 출력 | 현재 원문 편집기에서 인쇄 준비 |

로컬 저장만으로 사이트의 미저장 상태를 해제하지 않는다. 지원하지 않는 HWP 재저장과 호스트가 감지하지 못하는 문서 비교·교체 진입점은 계속 숨긴다. 편집 화면 내부에 문서를 드롭해도 사이트 업로드로 전달하며, 이미지 드롭은 기존 편집 동작을 유지한다. 여러 문서를 한꺼번에 놓으면 한 파일씩 열도록 안내한다.

부모 창은 현재 편집기 프레임과 같은 출처에서 온 메시지만 처리한다. 다른 출처나 이전 프레임의 메시지로 파일 작업을 실행하지 않는다.

## 작업 도구와 출력

원문 편집기 아래 `작업 도구` 또는 `Ctrl·Cmd+Shift+K`에서 작업별 기능을 모아 볼 수 있다.

- 내용 넣기: 표·그림·수식·특수문자·하이퍼링크·각주·미주·글상자·책갈피.
- 표 다듬기: 행·열 추가/삭제, 셀 병합/분할, 셀 속성·테두리, 크기 맞춤, 계산식.
- 쪽 구성: 편집용지·쪽/단 나누기·머리말·꼬리말·쪽 번호·쪽 테두리·구역 설정.
- 검토·출력: 찾기·바꾸기·이동·조판부호·인쇄·PDF 출력.

기존 편집 엔진의 명령과 현재 커서의 실행 가능 여부를 재사용한다. 지원하지 않거나 해당 위치에서 사용할 수 없는 명령을 실행 가능하다고 표시하지 않는다. 이전 검색 분류에서 빠지던 입력 필드와 기존 하이퍼링크 수정도 찾을 수 있다.

PDF 출력은 브라우저의 인쇄 대화상자에서 `PDF로 저장`을 선택하는 방식이다. 서버가 별도의 PDF 파일을 생성하는 기능은 아니다. 편집 중인 내용의 인쇄와, 서버 검증을 통과한 HWPX 다운로드는 구분한다.

문서 편집 보기에서 위쪽 파일 이름이나 도구에 초점이 있어도 Ctrl·Cmd+P는 문서 인쇄 준비로 전달한다. 다른 보기에서는 저장 후 문서 편집 보기로 이동하도록 안내해 사이트 메뉴 전체가 인쇄되는 실수를 막는다.

원문 편집 도구의 아이콘 스프라이트·파비콘·터치 아이콘 경로도 로컬 `/studio/` 자산으로 연결했다. 추가 기능은 필요할 때 불러와 상단 도구 막대를 늘리지 않는다.

## 임시 편집 보관함

문서 목록 메뉴의 `임시 편집 보관함`에서 이 브라우저의 원문 편집 임시본을 확인한다.

- 서버 보관 기간이 지났거나 세션 쿠키가 바뀐 문서의 임시본도 발견할 수 있다.
- 서버에 연결하지 않고 임시본 HWPX를 내려받을 수 있다. 임시본은 서버 검증을 완료한 결과물로 표시하지 않는다.
- `새 문서로 열기`는 임시본을 정상 업로드·분석 절차로 가져온다. 이전 문서와 보관함의 임시본을 덮어쓰거나 자동 삭제하지 않는다.
- 삭제는 항목별 확인 후 수행하며 현재 열린 문서의 임시본 삭제는 보관함에서 제한한다.
- 목록은 작은 메타데이터와 키만 읽어 큰 파일 바이트를 모두 복제하지 않는다. IndexedDB v1에 남은 이전 임시본도 키를 통해 발견하며 기존 바이트를 유지한다.
- 텍스트 편집 탭의 sessionStorage 임시본은 기존 방식으로 해당 탭에서 복원한다. 보관함은 원문 편집기의 IndexedDB 임시본을 대상으로 한다.

## 검증과 한계

실제 HWP 변환 후 이름 변경·복사, HWPX 최신 버전 복사·독립 편집·검증·다운로드, 원본 바이트·기존 버전 보존, 세션 격리, 충돌, 용량 제한, 복사 중 저장 오류를 검사한다. 브라우저 임시보관의 이전 스키마 유지·메타데이터 정렬·원자적 기록·삭제, 독립 파일 복구와 현재 임시본 보호도 검사한다.

테스트는 FastAPI TestClient, 실제 문서·WASM 엔진, React/jsdom 및 fake-indexeddb를 사용한다. 실제 브라우저 도구의 기존 접근 제한 때문에 브라우저 인쇄 창, 모바일 IME, 시각적 동일 조판을 확인했다고 주장하지 않는다. 한글의 모든 기능이나 모든 원본의 동일한 배치를 보장하는 단계는 아니다.

실행 기록은 비추적 로컬 경로 `build/validation/editor-functions-frontend.log`, `editor-functions-backend.log`, `editor-functions-build.log`에 보관한다.

확인 결과: 프런트엔드 전체 105개, 서버 전체 113개 통과 후 파일 관리·원문 저장·정적 자산 관련 21개 회귀 검사를 추가로 통과했다. 마지막 단축키 보완은 관련 UI 11개를 재검증했고 TypeScript 검사와 최종 빌드도 성공했다. 추가 패널은 지연 로딩을 유지하며 최종 메인 JS는 345.03KB, gzip 103.59KB다. 실행 중인 로컬 서버에도 새 API와 빌드 결과를 반영했다.
