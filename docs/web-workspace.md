# HWP · HWPX 웹 워크스페이스

기존 `jakal_hwpx` 엔진을 사용하는 로컬 웹 애플리케이션입니다. HWP 5·HWPX 업로드, 문단·표 셀 편집, 수정 버전 저장, 검증, 다운로드를 제공합니다.

현재 기본 화면은 **원문 서식 문서 편집기**입니다. 문서 위에서 직접 입력하고 글자·문단·표·그림·쪽 도구를 사용합니다. 왼쪽 목록을 접어 문서 영역을 넓혔으며, 기존 보기와 편집 방식도 남겨 두었습니다. 기능·저장 계약·로컬 빌드는 [원문 서식 편집기](page-editor.md)를 참고하세요.

## 실행

Python 3.11 이상과 Node.js 22.6 이상이 필요합니다. 저장소 루트에서 실행합니다.

Windows 최초 실행:

```powershell
.\scripts\start_web.ps1 -Install
```

이후 실행:

```powershell
.\scripts\start_web.ps1
```

화면 코드를 변경한 뒤에는 `-Rebuild`를 붙입니다. 브라우저에서 `http://127.0.0.1:8000`을 엽니다. 서버 종료는 터미널에서 `Ctrl+C`입니다.

플랫폼 공통 수동 설치·실행:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -e '.[web]'
cd web
npm ci
npm run build
cd ..
python -m server
```

프런트엔드 개발 시에는 API 서버를 실행한 상태에서 `web` 폴더의 `npm run dev`를 사용합니다. Vite가 `/api`를 로컬 API 서버로 전달합니다.

## 사용 방법

1. `.hwp` 또는 `.hwpx` 파일을 선택하거나 화면에 끌어놓습니다. HWP는 서버에서 HWPX로 변환한 뒤 같은 편집 흐름을 사용합니다. 샘플 열어보기로도 시작할 수 있습니다.
2. 파일은 **문서 편집**으로 열립니다. 원문 위를 클릭해 입력하고 상단 메뉴에서 서식을 바꾸세요. 아래로 스크롤하면 다음 쪽이 이어집니다. **원문 보기**로 전환하면 저장된 문서를 읽기 전용으로 확인할 수도 있습니다.
3. **표**에서는 수식·서식·병합을 포함한 원문 표 영역을 따로 봅니다. **셀 편집 목록**에서 수정할 표를 선택합니다. **그래프·그림**에서는 차트·삽입 그림·묶음 도형을 모아 보고 확대하거나 원문 페이지로 이동합니다. 선택한 영역은 PNG 이미지로 저장할 수 있습니다.
4. **텍스트 편집**은 **본문 이어 보기**가 기본입니다. 문단 번호·입력 상자 없이 문서처럼 읽고 수정합니다. 번호별로 확인하려면 **문단 목록**으로 전환합니다. 수정 뒤 **수정 저장**을 누르면 원본과 분리된 새 버전이 생성됩니다. 저장 전 편집은 실행 취소·다시 실행이 가능합니다.
5. **검증하기**를 누릅니다. XML 또는 HWP 바이너리 구조, 참조, 개체·첨부 보존과 저장 후 재열기를 검사합니다.
6. **다운로드**로 검증한 수정본을 받습니다. 이후 다시 수정하면 재검증해야 합니다.

원본에 이미 있던 검사 오류와 새로 생긴 오류를 구분합니다. 새 오류가 발생한 편집은 저장하지 않습니다. 원본의 기존 오류가 남은 경우 검증 결과에 표시하고 다운로드를 허용합니다. 검사 기록 JSON과 본문 TXT도 받을 수 있습니다.

## 지원 범위

- 기존 HWPX는 `HwpxDocument`로 직접 편집합니다.
- 새로 업로드한 HWP 5는 `@rhwp/core 0.8.7`로 HWPX로 변환합니다. 한글 설치나 외부 변환 서비스는 필요하지 않으며 Node.js와 `web/node_modules`가 서버에도 필요합니다. `JAKAL_NODE`로 Node 실행 파일을 지정할 수 있습니다. 업로드 HWP는 바이트 그대로 별도 보관하고, 변환된 HWPX를 편집·검증·다운로드합니다. 변환기가 내용 손실을 보고하면 처리를 중단하며 원본을 받을 수 있습니다. HWP 3·암호·배포용 문서는 지원하지 않습니다. 기존에 저장된 네이티브 HWP 문서는 호환 경로로 계속 열립니다.
- 병합 표는 행·열 병합 정보를 이용해 표시합니다. 표의 구조 변경은 지원하지 않습니다.
- 셀 안의 여러 문단은 줄바꿈으로 표시합니다. HWPX 텍스트 수정은 대상 문단·셀 내부의 글자별 서식을 단순화할 수 있습니다. HWP 혼합 서식 영역은 읽기 전용으로 보존합니다.
- 표·수식·그림·필드 등 복합 개체를 포함하는 문단·셀은 읽기 전용입니다. 개체를 포함하는 문단 안의 일반 텍스트도 이 버전에서는 수정할 수 없습니다.
- 원문 보기는 `@rhwp/core`의 브라우저용 WebAssembly 렌더러로 페이지·표·수식·그림을 그립니다. 한글 프로그램 자체의 화면이 아니므로 일부 글꼴·줄 배치·미지원 개체는 원본과 다를 수 있습니다. 최종 인쇄 배치는 한글에서 확인하세요. PDF 출력은 포함하지 않습니다.
- 암호화·배포용 문서, DTD가 있는 XML, 과도한 크기·깊이의 문서는 거부합니다. 일부 정상 문서도 이 웹 서비스의 제한으로 거부될 수 있습니다.
- 생성된 문서 내 스크립트·OLE 등은 서버와 브라우저에서 실행하지 않습니다. 원본의 임베디드 개체를 제거하는 서비스는 아닙니다.

## 고급 설정

편집 도구 모음의 **고급 설정**에서 문서별로 관리합니다.

- **편집 규칙**: 작업 메모(최대 8,000자, 참고용으로 저장), 보호 문구(100개·문구당 200자), 엄격 검증을 저장합니다. 설정은 문서 보관 기간 동안 SQLite에 남습니다. 다른 탭에서 설정을 변경하면 버전 충돌을 알립니다.
- **찾기·바꾸기**: 문단·표와 섹션 범위를 정해 일반 텍스트를 일괄 교체합니다. 정규식은 실행하지 않습니다. 변경 전후를 비교하고 선택한 항목만 편집에 추가합니다. 기존 미저장 편집에도 적용되며, 한 번의 실행 취소로 되돌릴 수 있습니다.
- 보호 문구는 대소문자를 구분하며, 각 문단·셀의 등장 횟수가 바뀌는 수정을 차단합니다. 수동·일괄 편집 모두 서버에서 다시 검사합니다.
- 엄격 검증을 켜면 원본의 기존 오류도 저장·검증을 차단합니다. 옵션을 바꾸면 현재 버전의 재검증이 필요합니다.

## 원문 뷰어

### 본문 편집 화면

본문 이어 보기에서는 실제 문장 길이와 화면 폭에 맞춰 입력 영역이 늘어나며 내부 스크롤이나 줄 수 제한으로 내용을 숨기지 않습니다. 기본·큰·더 큰 글씨를 선택할 수 있습니다. 빈 문단과 내용 없는 복합 개체의 반복 안내는 숨기고, 읽기 전용 문장은 문맥을 위해 함께 표시합니다. 수식·그림의 정확한 표현은 원문 보기에서 확인합니다.

본문 검색은 주변 문장을 제거하지 않습니다. Enter / Shift Enter 또는 검색 결과의 위·아래 버튼으로 일치하는 구간을 이동합니다. 문단 목록에서는 기존처럼 검색 결과만 표시하고 빈 문단·읽기 전용 문단 표시 여부를 선택할 수 있습니다. 보기 전환 시 미저장 변경과 실행 취소 기록은 유지됩니다.

본문 이어 보기의 위·아래 화살표는 입력 칸의 처음·끝에서 이전·다음 편집 가능한 내용으로 이동합니다. 기존 문서의 문단 구조는 유지하며 Enter는 해당 문단 안의 줄바꿈입니다. 모바일은 편집 도구도 기본적으로 접고 실행 취소·다시 실행·수정 저장을 남깁니다. 도구 버튼 또는 Ctrl/Cmd F로 메뉴와 검색을 펼칠 수 있습니다.

### 미저장 편집과 변경 검토

미저장 편집은 이 탭의 `sessionStorage`에 약 0.4초 뒤 임시보관합니다. 창을 나갈 때도 마지막 입력을 보관하며, 새로고침 뒤 같은 문서·같은 저장 버전·같은 편집 대상일 때만 자동 복원합니다. 실제 파일을 바꾸려면 **수정 저장** 또는 `Ctrl/Cmd S`를 실행해야 합니다. 임시보관 용량은 문서당 200만 자이며, 브라우저 저장소가 차단되거나 용량을 넘으면 화면에 보관 불가를 표시합니다. 탭을 닫으면 임시본이 사라지므로 파일 저장을 대신하지 않습니다.

임시보관 상태 옆의 다시 불러오기 버튼은 현재 편집을 먼저 보관하고 최신 문서를 엽니다. 다른 탭에서 저장 버전이 바뀌면 이전 초안을 자동 적용하지 않고 별도로 보관합니다. **임시본문 받기**로 변경 전후를 텍스트 파일로 받은 뒤 이전 초안을 정리할 수 있습니다. 이전 보관본이 남아 있는 동안은 현재 편집으로 덮어쓰지 않습니다. 각 탭은 마지막으로 열었던 문서도 별도로 기억합니다.

**수정 내용** 또는 하단의 **변경 · 검토**에서 문단·표 셀의 변경 전후를 모아 보고 검색합니다. 각 항목의 **이동**은 해당 편집 위치를 열고, **되돌리기**는 그 항목만 취소합니다. **전체 되돌리기**는 모든 미저장 변경을 한 번에 취소합니다. 개별·전체 되돌리기 모두 실행 취소로 복원할 수 있습니다. 긴 목록은 30개씩 표시합니다.

다운로드 버튼은 문서 상태에 따라 **저장·검증 후 다운로드**, **검증 후 다운로드**, **다운로드**로 표시합니다. 필요한 단계만 순서대로 실행하고, 중간에 저장·검증이 실패하거나 다른 탭에서 버전이 바뀌면 다운로드를 중단합니다. 저장이 성공하고 검증이 실패한 경우에는 저장된 버전을 유지하며, 저장 자체가 실패한 경우에는 미저장 편집을 유지합니다.

### 원문 읽기

원문 파일은 세션 소유권을 확인하는 `/api/documents/{id}/source?revision=N`으로 가져옵니다. 업로드 원본(0)과 현재 저장 버전만 읽을 수 있습니다. 원본 파일은 변경하지 않으며, 읽기 전용 뷰어에서는 저장 기능을 사용하지 않습니다. 수정본이 있는 문서는 ‘업로드 원본 보기’로 비교할 수 있습니다. 저장 전 변경은 뷰어에 반영되지 않았음을 표시합니다.

HWP 변환 문서의 `source?revision=0`은 변환 직후의 HWPX입니다. 업로드된 파일 자체는 소유권을 확인하는 `/original`에서 받습니다. 변환 상태·엔진·내용 손실 보고서를 스냅샷에 함께 기록합니다. 변환은 60초, 출력 20MB로 제한하며 작업의 하위 프로세스도 768MB 합산 메모리·120초 제한과 종료 처리에 포함합니다. 변환이 성공해도 모든 한글 기능과 픽셀 단위 배치를 보장하지는 않습니다.

문서 배율은 10~400%, 너비 맞춤, 한 쪽 맞춤을 지원합니다. `Ctrl/Cmd +`, `−`, `0`과 뷰어 위 `Ctrl/Cmd + 휠`, 두 손가락 벌리기로 조절할 수 있습니다. 확대 시 보고 있던 위치를 유지하고 문서 내부에서 가로·세로로 이동합니다. 모바일에서는 탐색·배율·검색 도구를 나누어 표시하고, 가로 화면과 전체 화면에 맞춰 재배치합니다.

원문은 연속 스크롤로 배치하며 가까운 페이지만 SVG DOM에 표시합니다. 화면 밖의 쪽도 높이를 유지해 페이지가 로드될 때 스크롤 위치가 밀리지 않습니다. 라이브 페이지는 최대 24개, 브라우저 SVG 캐시는 24쪽·3,200만 자로 제한합니다. 표·그림의 원문 위치 링크는 해당 쪽으로 이동하며 탭을 오가면 읽던 위치를 복원합니다.

읽기 도구 오른쪽의 **접기 / 도구** 버튼으로 상단 제목·탭·검색·원본 다운로드 줄을 접고 펼칩니다. 접혀도 현재 쪽, 배율, 펼치기 버튼은 남습니다. 데스크톱에서는 아래로 100px 이상 스크롤하면 자동으로 접고, 모바일에서는 처음부터 접어 문서 영역을 확보합니다. 직접 펼치면 현재 문서에서는 자동 접기를 중단합니다. `Ctrl/Cmd F`도 도구를 펼쳐 검색으로 이동합니다. 편집·표·그림 탭에서는 전체 작업 도구를 표시합니다.

파싱·페이지 계산은 별도 Web Worker에서 실행합니다. WASM은 같은 서버에서 제공하며 외부 문서 변환 서비스에 파일을 보내지 않습니다. 초기 로드는 최대 60초, 페이지 렌더링은 45초로 제한합니다. 최대 500쪽·그래프/그림/표 각각 5,000개, 검색용 텍스트는 문서당 200만 자까지 수집하며 각 페이지 SVG는 12MB 이하여야 합니다. 원문은 필요한 페이지만 그리고 그래프 목록은 12개씩 추가 표시합니다.

SVG는 DOMPurify와 추가 URL 검사로 정리합니다. 문서가 삽입한 스크립트·외부 링크·프레임은 실행하지 않으며 이미지의 외부 URL도 제거합니다. 그래프와 표의 별도 보기는 페이지에서 해당 영역을 잘라 PNG로 보여 주므로 겹쳐 놓인 내용이 함께 포함될 수 있습니다. 다운로드에도 선택한 영역의 픽셀만 포함합니다. 수식·단순 선·머리말 장식은 그래프 목록에서 제외하고 원문에서 표시합니다.

키보드: 좌우 화살표로 페이지 이동, 페이지 번호 입력 후 Enter로 직접 이동, Ctrl/Cmd+F로 원문 검색, Enter/Shift+Enter로 다음/이전 검색 페이지 이동. 전체 화면은 Esc로 종료합니다.

## 저장소와 작업 실행

이전 저장 내용의 비교와 새 버전 복원은 **보기 및 도구 → 버전 기록**에서 사용합니다. 동작과 API는 [저장 버전 기록과 복원](version-history.md)에 정리했습니다.

동시 업로드, 저장 완료 조건, 오류·재시작 복구의 세부 동작은 [백엔드 저장 및 작업 복구](backend-reliability.md)에 정리했습니다.

`server/app.py`는 세션·업로드·다운로드 API, `server/engine.py`는 허용된 문서 작업 어댑터, `server/worker.py`는 작업별 하위 프로세스를 담당합니다. `server/storage.py`가 SQLite에 작업과 문서 버전을 기록합니다. 웹 소스는 `web/src/`에 있습니다.

이 1차 버전은 **단일 호스트·단일 API 프로세스**용입니다. 별도 PostgreSQL 설치 없이 실행하도록 SQLite를 사용합니다. 서버를 여러 인스턴스/워커로 실행하지 마세요. 수평 확장 시 작업 소유권·만료 lease를 포함한 PostgreSQL/전용 큐 어댑터가 필요합니다.

- 파일: 기본 `.web-data/<문서 ID>/revision-N.hwp` 또는 `revision-N.hwpx`
- 문서 정보·검사 결과: 같은 디렉터리의 `snapshot-N.json`
- 작업 기록: `.web-data/app.sqlite3`
- 원본: `revision-0.hwp` 또는 `revision-0.hwpx`, 편집 시 덮어쓰지 않음
- 작업: DB의 대기 작업을 단일 워커가 가져와 별도 Python 프로세스로 실행
- 종료·재시작: 실행 중이던 작업은 실패로 표시, 대기 작업은 이어서 실행
- 보관: 업로드 시점부터 24시간, 실행 중에는 60초 주기로 정리하며 서버 재시작 시에도 정리
- 접근: HttpOnly·SameSite 세션 쿠키 소유자만 접근, 만료 문서는 정리 전에도 접근 차단
- 보안·사용 종료: 세션 폐기, 문서 즉시 만료, 브라우저 임시본·내 양식 삭제. 세부 정책은 [문서 비공개 저장과 공개 배포](document-privacy.md) 참고
- 한도: 파일 20MB, 압축 해제 합계 128MB, 내부 파일 4,096개, 내부 파일당 24MB, 세션당 문서 20개
- 워커 제한: 작업당 120초, 프로세스 메모리 768MB. Linux/macOS는 추가 CPU 시간 제한 사용

세션 쿠키를 지우면 문서 접근 권한이 사라집니다. 파일은 원래 만료 시점에 삭제됩니다. 서버가 꺼져 있는 동안은 디스크 정리가 실행되지 않습니다. 원본 파일명과 문서 내용은 로컬 데이터 디렉터리에 평문으로 보관되며 Git에서 제외됩니다.

설정:

| 환경 변수 | 기본값 | 용도 |
|---|---|---|
| `JAKAL_DATA_DIR` | 저장소의 `.web-data` | 문서와 DB 저장 위치 |
| `JAKAL_HOST` | `127.0.0.1` | 서버 바인딩 주소 |
| `JAKAL_PORT` | `8000` | 서버 포트 |
| `JAKAL_COOKIE_SECURE` | 미설정 | HTTPS 운영 시 `1`로 설정 |
| `JAKAL_ENV` | `development` | 공개 배포는 `production` 필수 |
| `JAKAL_PUBLIC_ORIGIN` | 미설정 | 운영 시 허용할 전용 HTTPS origin |
| `JAKAL_TRUSTED_PROXIES` | `127.0.0.1` | HTTPS scheme을 전달할 신뢰 프록시 IP, 운영에서 `*` 금지 |

현재 기본 실행은 사용자 컴퓨터의 루프백 접속만 허용합니다. 공개 서비스는 [운영 모드·HTTPS·저장소 정책](document-privacy.md)에 따라 실행하세요. 공개 배포용 인프라, 프록시의 요청 속도 제한, 전체 저장 용량 제한, 계정 인증, 서버 간 작업 큐와 OS 프로세스 격리는 별도로 구성해야 합니다. Sites 등 프런트엔드 호스팅과 연결하려면 Python API 서버를 별도로 배포해야 합니다.

## 검증

```bash
python -m pip install -e '.[web,web-test]'
python -m pytest web_tests -q
cd web
npm ci
npm test
npm run build
```

프런트엔드 테스트는 특수문자·빈 문자열·대소문자·보호 문구·과도한 치환 결과, SVG의 활성 콘텐츠 제거, 그림 영역 자르기, 검색 강조와 실제 HWP/HWPX 수식 문서 렌더링을 검사합니다. 수정 이력은 변화 없는 입력의 다시 실행 기록 보존, 일괄 수정의 단일 실행 취소, 최대 60단계 이력을 검사합니다. 브라우저 저장소 차단·용량 초과도 문서 작업을 중단하지 않도록 검사합니다.

본문 이어 보기에서는 바뀐 문단만 다시 렌더링하고, 화면 폭·글자 크기·웹폰트 로딩에 따른 입력칸 높이는 한 번에 측정합니다. 글꼴이 늦게 로드되어 줄바꿈이 달라져도 입력 내용이 잘리지 않도록 높이를 다시 맞춥니다. 마지막 문서 기억은 선택적 브라우저 설정이며, 저장소를 사용할 수 없더라도 현재 문서를 열고 수정할 수 있습니다.

API 테스트는 실제 워커 프로세스를 실행하여 파일 업로드 → 문단·셀 수정 → 검증 → 다운로드 → 엔진 재열기를 확인합니다. 원본 보존, 검증 버전 불일치, 세션 격리, 실패 시 수정 버전 보존, 업로드 제한, 만료·삭제도 검사합니다.

실제 수식 HWP·다중 섹션 수식 HWPX·신청서 HWPX로 다운로드 후 재업로드까지 검사합니다. 변환 중 생긴 XML·첨부 참조 오류는 원본의 기존 오류로 취급하지 않고 변환 단계에서 차단합니다. 검사 파일과 확인 내용은 [실제 파일 검사 기록](qa-roundtrip.md)에 정리했습니다.

샘플 문서는 저장소 코드로 생성한 테스트용 자료입니다. 다시 만들려면 `python scripts/create_web_sample.py`를 실행합니다.

## UI 참고 자료와 에셋

현재 문서 편집 중심의 중립적인 디자인을 유지하며 고급 기능은 보조 패널에 모았습니다. [NN/g의 Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)와 [Fluent의 Drawer 사용 지침](https://fluent2.microsoft.design/components/web/react/core/drawer/usage)을 참고했습니다.

한글 글꼴은 [Spoqa Han Sans Neo](https://github.com/spoqa/spoqa-han-sans)의 Regular·Medium·Bold 서브셋을 자체 제공하며 외부 폰트 요청은 하지 않습니다. 드문 글자는 시스템 글꼴로 대체될 수 있습니다. SIL OFL 라이선스는 `web/public/fonts/LICENSE.txt`에 포함했습니다. 기존 Lucide 아이콘은 선 굵기를 통일하고 브랜드와 파비콘 색을 맞췄습니다.

원문 뷰어는 [rhwp](https://github.com/edwardkim/rhwp)의 `@rhwp/core` 0.8.7(MIT)을 사용합니다. SVG 정리는 DOMPurify 3.4.17을 사용하며 관련 라이선스는 `web/public/licenses/`에 포함했습니다. 패키지 버전은 lockfile로 고정합니다.
