# DOCX 변환 재현 기준

[`representative.docx`](../examples/samples/docx/representative.docx)는 이 저장소에서 직접 만든
DOCX→HWPX/HWP 회귀 문서입니다. 본문 글자 서식과 색상, 자동 목록, 병합 표,
표 테두리·셀 음영, 그림, 첫 페이지 전용 머리말, 단순 수식을 함께 담았습니다.
외부 파일의 저작권이나 가용성에 의존하지 않도록
`python scripts/build_docx_fidelity_sample.py`로 다시 만들 수 있습니다.

`python -m pytest tests/test_docx_fidelity_sample.py`는 한글 프로그램 없이 두 형식으로
저장한 뒤 다시 열어 텍스트, 표 색상·테두리 참조, 수식 컨트롤을 확인합니다.
검사는 파일 구조의 보존 여부를 확인하며 페이지 배치나 글꼴 렌더링의 시각적
동일성을 판정하지는 않습니다.

| 요소 | 현재 변환 상태 |
| --- | --- |
| 본문 글자 서식·색상, 인라인 그림 | HWPX/HWP 구조 검사 통과 |
| 병합 표, 직접 지정한 테두리·셀 배경색 | HWPX/HWP 구조 검사 통과 |
| 단순 선형 Word 수식 | HWPX/HWP 수식 컨트롤로 변환 |
| 글머리표·십진·로마·영문 번호 | HWPX 누름틀에 표시값과 목록 정의 보존; DOCX로 돌아오면 자동 목록 복원 |
| 첫 페이지 전용 머리말·꼬리말 | HWPX 첫 페이지 고정 글상자로 표시; DOCX의 첫 페이지 전용 영역으로 복원 |
| 현재 페이지 번호 | HWPX 자동 번호와 Word PAGE 필드로 연결 |
| 일반 Word 필드 | HWPX에 표시값·명령 보존; DOCX에서 필드 명령 복원 |
| 각주·미주 | 양쪽의 참조·주석 영역으로 연결; 혼합 서식·그림·표 보존 검사 |
| 변경 추적·콘텐츠 컨트롤 | 변경 수락 후의 보이는 내용으로 변환; 원본 DOCX의 이력·바인딩은 그대로 보존 |
| 지원하지 않는 Word 수식 구조 | 원본 DOCX는 보존하고 파이썬 변환은 오류로 중단 |
| 테마 기반 표 서식 | 직접 지정한 서식 외의 조건부 효과는 손실될 수 있음 |

완전 재현 여부를 주장하려면 구조 검사와 별도로 같은 글꼴 환경에서 DOCX와
변환 결과의 페이지 수, 텍스트 위치, 표 경계, 그림 위치를 비교해야 합니다.

## 양방향 왕복 검증

`python -m pytest tests/test_docx_roundtrip.py`는 다음 계약을 확인합니다.

- DOCX → HWPX → DOCX에서 표 셀의 혼합 글자 서식, 링크, 그림과 중첩 표를 유지합니다.
- 머리말·꼬리말의 혼합 글자 서식과 그림을 유지합니다.
- 문단 간격·들여쓰기·줄 간격·탭 위치와 채움선을 세 번 왕복해도 누적 변경하지 않습니다.
- 기본 Word 표의 왼쪽 정렬, 위쪽 세로 정렬과 기본 셀 여백을 명시적으로 변환합니다.
- 스타일 이름, 빈 작성자, 생성·수정 날짜를 유지합니다.
- 분수·첨자·근호를 양쪽의 수식 구조로 옮기며, 지원하지 않는 Word 수식을 이어 붙여 다른 식으로 만들지 않습니다.
- 그림만 있는 문단의 정렬과 네이티브 HWPX 테두리·여백을 유지합니다.

2026-10-28 로컬 시각 검증은 본문 혼합 글자 서식, 오른쪽 탭과 점 채움선,
음영 표의 혼합 서식·그림·중첩 표, 분수, 머리말 그림·굵은 글자, 기울인 꼬리말을
함께 넣은 Letter 1페이지 샘플로 수행했습니다. 양방향으로 두 번 왕복한 뒤 실제
Microsoft Word와 한컴오피스에서 PDF를 출력하고 144 DPI PNG로 비교했습니다.

| 비교 | 텍스트 / 페이지 수 / 크기 | 픽셀 차이 |
| --- | --- | --- |
| 원본 DOCX와 DOCX → HWPX → DOCX | 일치 | 0% |
| 위 DOCX와 두 번째 왕복 DOCX | 일치 | 0% |
| 초기 HWPX와 HWPX → DOCX → HWPX | 일치 | 0% |
| 위 HWPX와 두 번째 왕복 HWPX | 일치 | 0% |

Word 결과는 Word끼리, HWPX 결과는 한컴끼리 비교한 수치입니다. 서로 다른 조판
엔진의 출력을 같다고 본 것이 아닙니다. 같은 샘플의 Word와 한컴 출력 사이에는
약 3.05%의 변경 픽셀과 PDF 용지 높이 차이가 남습니다. 페이지는 확대·축소하지 않고
RGB 채널 차이 24를 넘는 픽셀의 비율을 측정했으며, 위의 0%는 픽셀 배열 자체도
동일함을 확인했습니다.

이 결과는 이 샘플과 위 테스트의 지원 항목에 한정됩니다. 모든 네이티브 도형과
Word 확장 기능을 포함하는 임의의 문서가 완전히 호환된다는 뜻은 아닙니다.

## 대체 표현의 왕복 계약

`python -m pytest tests/test_docx_effect_mapping.py`는 아래 대체 표현을 검사합니다.

- `HeaderFooter.apply_page_type="FIRST"`를 첫 페이지에만 존재하는 글상자로 저장합니다.
  선과 채우기를 제거하고 용지 기준으로 배치해 본문 줄바꿈에 영향을 주지 않습니다.
  일반 머리말·꼬리말은 첫 페이지에서 숨깁니다. 역변환할 때 글상자의 실제 내용을
  Word 첫 페이지 전용 영역으로 되돌립니다. 그림·혼합 서식과 가로 용지도 검사합니다.
- 목록은 HWPX의 `CLICK_HERE` 누름틀로 번호·글머리표를 표시합니다. 들여쓰기,
  목록용 탭, 같은 스타일 사이의 문단 간격을 계산하며, 번호 시작값과 단계 정의를
  함께 보존합니다. Word로 돌아오면 `numbering.xml`과 `numPr`을 생성하므로
  목록을 추가하거나 삭제할 때 다시 번호가 갱신됩니다. HWPX 안에서 번호 자체를
  자동 갱신하지는 않습니다. 표시 번호를 직접 바꿨다면 역변환에서도 그 문자열을 유지합니다.
- 일반 필드는 누름틀 표시값과 원래 Word 명령을 보존합니다. HWPX에서 Word 명령을
  계산하지는 않으며, 현재 페이지 번호는 별도로 한글의 자동 번호에 연결합니다.
- 한글 재저장은 사용자 정의 필드 매개변수를 제거할 수 있습니다. 따라서 작은 기능
  정의를 누름틀 이름에도 압축해 보관합니다. 원본 문서 전체를 숨겨 넣는 방식이 아닙니다.
  누름틀 이름을 유지해야 이 정보로 복원할 수 있습니다. 같은 run 안으로 필드 경계와
  표시값이 합쳐져도 읽고 수정할 수 있으며, 주변 본문은 건드리지 않습니다.
- 각주·미주는 본문 참조와 별도 Word 파트/HWPX 주석 영역으로 옮깁니다. 주석 파트
  안의 그림 관계, 표, 글자 서식을 보존합니다. 단독 페이지 나눔은 다음 문단이나 표에
  연결하여 새 페이지 위에 불필요한 빈 줄을 만들지 않습니다.
- 콘텐츠 컨트롤과 삽입·이동된 내용은 실제 보이는 글·표로 펼칩니다. 삭제·이동 전
  내용은 수락된 보기에서 제외합니다. 원본 DOCX 저장과 Word 전용 편집은 원본 구조를
  사용하므로, 이 투영 때문에 변경 이력과 바인딩이 원본에서 삭제되지는 않습니다.

2026-10-28 추가 시각 검증은 첫 페이지/일반 머리말·꼬리말, 목록, PAGE·DOCPROPERTY,
각주·미주를 넣은 2페이지 문서를 사용했습니다. 실제 Word와 한글에서 PDF를 출력해
144 DPI로 비교했고, 한글에서 HWPX를 다시 저장한 뒤에도 목록 정의와 Word 필드 명령이
복원됨을 확인했습니다.
다음 표는 참조번호 서식 보존 수정 전의 측정 기록이며, 수정 후 결과는 마지막 절에 있습니다.

| 비교 | 페이지 수 | 페이지 전체를 분모로 한 변경 픽셀 |
| --- | --- | --- |
| 원본 DOCX → 첫 번째 왕복 DOCX, Word 출력끼리 | 2 → 2 | 약 0.170%, 0.105% |
| 첫 번째 → 세 번째 왕복 DOCX, Word 출력끼리 | 2 → 2 | 0%, 0% (픽셀 배열 동일) |
| 초기 → 세 번째 HWPX, 한글 출력끼리 | 2 → 2 | 0%, 0% (픽셀 배열 동일) |

첫 변환의 차이까지 0%라는 뜻은 아닙니다. 이 백분율은 흰 여백을 분모에 포함하므로
내용의 일치율로 해석해서는 안 됩니다. 첫 번째와 세 번째 결과의 일치는 첫 변환에서
바뀐 상태가 반복 유지됨을 의미합니다. 서로 다른 조판 엔진의 동일성도 보장하지 않습니다. 큰 첫 페이지
머리말이 본문 영역까지 차지하는 문서, 복잡한 주석 번호 재시작과 사용자 구분선은
추가 문서별 검증이 필요합니다. 순수 파이썬 HWP 출력은 목록·필드를 표시 문자열로,
첫 페이지 영역을 글상자의 텍스트로 보존하므로 HWPX 경로의 풍부한 서식 복원 계약과
구분해야 합니다. 지원 밖 수식, 주석 범위, 레거시 OLE/도형 등은 여전히 별도 매핑이나
명시적 네이티브 변환기가 필요한 항목입니다.

## 흰 배경을 제외한 차이 원인 재검증

같은 2페이지 샘플을 다시 분석했습니다. 동일한 Word 조판 엔진으로 출력한 원본과
첫 왕복 결과를 비교했으며, 각 페이지는 144 DPI의 1224 × 1584 픽셀입니다.
각 이미지에서 RGB 채널 중 하나라도 245 미만인 픽셀을 표시 영역으로 잡고,
원본과 결과의 표시 영역 **합집합**을 분모로 삼았습니다. 원본에서 사라진 부분과
결과에 새로 생긴 부분을 모두 포함합니다. 변경 판정은 기존과 같이 RGB 채널 차이
24 초과입니다. 이 정의는 배경이 흰색인 이 샘플에 대한 것으로, 유색 배경 문서에는
그대로 일반화하지 않습니다. 표시 영역이 없는 빈 페이지는 이 비율로 평가하지 않습니다.

| 페이지 | 변경 픽셀 | 표시 영역 합집합 | 전체 페이지 기준 차이 | 표시 영역 기준 차이 | 표시 영역 IoU |
| --- | --- | --- | --- | --- | --- |
| 1 | 3,295 | 8,830 | 0.170% | **37.316%** | 69.785% |
| 2 | 2,036 | 6,248 | 0.105% | **32.586%** | 77.753% |

IoU는 표시 픽셀의 교집합을 합집합으로 나눈 값이며 문서 정합률이나 글자 인식률은
아닙니다. 공백을 제외한 추출 문자열은 같았지만 번호의 크기와 글자의 위치가 달랐습니다.
표시 영역 차이는 아래 세 영역에 전부 포함되었으며, 세 영역 바깥의 변경 픽셀은 0개였습니다.

| 영역 | 직접 확인한 변화 | 해당 영역의 변경 픽셀 |
| --- | --- | --- |
| 1페이지 본문 참조번호와 뒤의 필드 표시값 | 참조번호 11.04 → 6.96pt; 뒤의 글자가 왼쪽으로 3.48pt 이동 | 1,042 |
| 1페이지 각주 줄 | 참조번호 11.04 → 6.96pt; 주석 글자가 왼쪽으로 2.28pt 이동 | 2,253 |
| 2페이지 미주 줄 | 참조번호 11.04 → 6.96pt; 주석 글자가 왼쪽으로 1.20pt 이동 | 2,036 |

원인은 현재 `addons/docx/writer.py`로 옮겨진 `_Writer.note()`가 본문 참조번호와 주석 안의 참조번호를
모두 `vertAlign=superscript`로 생성하던 코드였습니다. 이 샘플 원본의 네 참조번호는
본문과 같은 크기였으며, 번호를 작게 바꾼 결과 번호 뒤의 글자가 당겨졌습니다.
수정 전에는 원본 참조번호의 글자 서식이 공통 `Note` 모델에 전달되지 않았습니다.

원인 분리 실험에서는 변환 결과의 임시 DOCX 사본에서 해당 **네 위첨자 설정만** 제거하고
다시 Word로 출력했습니다. 두 페이지 모두 원본과 픽셀 배열이 완전히 같았고 최대 RGB
차이도 0이었습니다. 따라서 이 샘플에서 구분선, 머리말, 목록이나 조판 엔진 차이를
원인으로 들었던 설명은 정정합니다. 확인된 수정 대상은 참조번호 서식의 수입·보존·복원입니다.
정상적으로 위첨자를 쓰는 원본도 있으므로 모든 참조번호를 일반 글자로 바꾸는 방식은
일반 해법이 아닙니다. 위첨자 설정을 일괄 삭제하는 대신 아래의 원본 서식 보존 경로로
변환기를 수정했습니다.

## 참조번호 서식 보존 수정 후 검증

`Note.reference_run_properties`와 `Note.marker_run_properties`에 본문 참조번호와
주석 내부 번호의 서식을 각각 보존합니다. Word의 직접 서식, 문자·문단 스타일과
문서 기본값을 읽어 독립적인 run 속성으로 만들며, 해석 가능한 테마 글꼴은 실제 글꼴
이름으로 기록합니다. 일반 글자·위첨자·아래첨자, 글꼴·크기·색상·강조뿐 아니라
자간과 명시적인 세로 위치도 유지합니다. 새 Word 문서에서 존재하지 않을 수 있는
문자 스타일 ID에 의존하지 않습니다.

HWPX에서는 참조번호의 문자 모양을 연결하고, 원본 Word 속성은 주석 내부의 빈
`CLICK_HERE` 필드에 보관합니다. 필드 이름에도 같은 작은 기능 정의를 보존하므로
한글 재저장으로 사용자 매개변수가 제거되어도 복원할 수 있습니다. 빈 필드는 글자를
출력하지 않으며 Word 복원 전에 공통 주석 내용에서 제거합니다. 원본 Word 서식 정보가
없는 기존 HWP/HWPX 주석의 기본 위첨자 동작은 유지합니다.

실제 수정된 변환기로 DOCX → HWPX → DOCX를 실행해 Word에서 다시 출력했습니다.
원본과 결과의 흰 배경을 제외한 표시 영역 합집합 기준 결과는 다음과 같습니다.

| 샘플 / 경로 | 페이지 수 | 수정 전 변경 픽셀 | 수정 후 변경 픽셀 | 수정 후 표시 영역 차이 | 수정 후 표시 영역 IoU |
| --- | --- | --- | --- | --- | --- |
| 기존 2페이지 샘플 1쪽 | 2 → 2 | 3,295 | 0 | **0%** | 100% |
| 기존 2페이지 샘플 2쪽 | 2 → 2 | 2,036 | 0 | **0%** | 100% |
| 기존 샘플을 세 번 왕복 후 원본과 비교 | 2 → 2 | — | 두 쪽 모두 0 | **0%** | 100% |
| HWPX를 실제 한글에서 재저장한 뒤 DOCX로 복원 | 2 → 2 | — | 두 쪽 모두 0 | **0%** | 100% |
| 초기 HWPX와 세 번째 HWPX, 한글 출력끼리 | 2 → 2 | — | 두 쪽 모두 0 | **0%** | 100% |
| 본문 번호는 위첨자, 각주 안 번호는 일반 글자 | 1 → 1 | — | 0 | **0%** | 100% |
| 본문 번호는 일반 글자, 미주 안 번호는 위첨자 | 1 → 1 | — | 0 | **0%** | 100% |

수정 후의 모든 위 비교에서 임계값을 적용하기 전 RGB 픽셀 배열도 동일했습니다. 공백을 제외한
문자열, PDF에 기록된 글꼴 계열과 글자별 좌표·크기를 함께 비교했으며 최대 글자 위치
차이와 글자 크기 차이는 모두 **0pt**였습니다. 별도 서식 샘플은 상속된 Arial 14pt의
본문 번호와 Courier New 9pt의 주석 번호, 서로 다른 색상·강조·자간·세로 위치를 사용했습니다.
이 수치는 해당 샘플과 경로의 측정 결과입니다.

`python -m pytest tests/test_note_reference_formatting.py tests/test_render_comparison.py`로
참조번호 서식의 독립적인 3회 왕복, 일반/위/아래첨자, 원본 DOCX 무수정 보존,
한글 필드 매개변수 정규화와 흰 여백에 영향을 받지 않는 비교 지표를 검사합니다.

PNG 비교는 다음 명령으로 재현할 수 있습니다. 이미지 로딩에는 Pillow가 필요하며
두 페이지는 같은 DPI와 크기여야 합니다. 이 도구는 크기를 맞추거나 글자 위치를
자동 정렬하여 오차를 숨기지 않습니다. 빈 페이지의 표시 영역 점수는 `null`입니다.

```sh
python scripts/compare_document_renders.py original-page.png returned-page.png --output foreground.json
```
