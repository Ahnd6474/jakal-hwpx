# 편집 화면 정리와 지연 최적화

이후 실제 타이핑 지연을 추가 측정하고 글꼴 해석·화면 갱신·IME 중 임시 저장을 개선했습니다. 최신 내용은 [입력 지연 개선](input-latency.md)에 정리했습니다.

2026-10-20, 동일한 로컬 미리보기와 예제 문서로 확인했습니다.

## 화면

문서 이름·보기 메뉴·저장·다운로드를 한 줄에 배치했습니다. 별도의 보기 탭 줄과 편집 안내 줄은 제거했습니다. **보기 및 도구** 메뉴에서 원문·텍스트·표·그림 보기, 검증·문서 정보·고급 설정에 접근합니다. 키보드 방향키와 Escape로도 메뉴를 사용합니다.

편집기는 기본적으로 글꼴·크기·강조·정렬 등 기본 서식만 표시합니다. 아래의 **모든 도구**는 기존의 전체 도구를 펼칩니다. **집중 보기**는 편집 메뉴와 서식 줄을 접고, **편집 도구 복귀**로 돌아옵니다. 확대·너비 맞춤·전체 화면과 저장 상태는 문서 아래에 모았습니다. 입력·선택·단축키와 기존 편집 명령은 유지했습니다.

1280×720 화면에서 동일한 예제 파일을 열어 DOM 경계를 측정했습니다. 문서 스크롤 영역은 기존 388px → 기본 538px → 집중 보기 602px입니다. 기본 화면은 위쪽 공간 약 150px를 되찾았습니다. 모바일 390px 화면에서도 페이지 전체의 가로 넘침이 없는지 확인했습니다.

## 지연 감소

- 임시 저장은 연속 입력이 멈춘 뒤 2.5초를 기다리고 브라우저 유휴 시간에 실행합니다. 반복 압축은 최소 10초 간격으로 제한합니다. 내보내기 실행 중에는 다른 임시 저장을 겹쳐 실행하지 않으며, 오래된 작업 결과가 최신 임시본으로 표시되지 않도록 검사합니다. 탭이 배경으로 가면 대기 중인 임시 저장을 바로 시도합니다. 명시적 수정 저장은 이 대기 시간을 적용하지 않습니다.
- 같은 입력에서 발생하는 변경 알림을 프레임당 한 번으로 모으고, 변경 여부가 실제로 바뀔 때만 앱에 전달합니다. 편집기 React 컴포넌트와 저장 콜백도 안정화했습니다.
- 편집기 초기화, 원본 파일 다운로드, 임시본 조회를 동시에 시작합니다. 별도 원문 뷰어는 해당 보기를 처음 열 때 시작하는 방식을 유지합니다.
- JS·CSS·WASM은 빌드할 때 gzip 파일을 만듭니다. 서버가 매번 압축하지 않고 브라우저의 인코딩 지원에 맞춰 제공합니다. 해시가 있는 파일은 장기 캐시하고, HTML·통합 CSS는 재검증하며, 문서 API는 `no-store`를 유지합니다. 공개 파일 응답에는 세션 쿠키를 넣지 않습니다.
- 작업 상태 요청은 서버에서 최대 1.2초간 완료를 기다립니다. 기존 400ms 간격 폴링에 따른 완료 확인 대기를 줄이고 반복 HTTP 요청도 줄였습니다. 기존 서버와 연결할 때도 과도한 반복 요청을 방지합니다.
- 전체 문서 저장에서 이전 버전 텍스트가 필요하지 않은 경우 이전 ZIP을 다시 여는 작업을 제거했습니다. 보호 문구 설정이 있으면 이전 파일을 열어 동일한 검사를 수행합니다.

빌드한 압축 대상 정적 파일 합계는 약 35.01MB → 12.77MB로 약 64% 줄었습니다. 실제 편집기 WASM 응답은 11,821,756바이트 → 4,425,599바이트이며 gzip·캐시 헤더도 확인했습니다. 이 수치는 파일 크기 비교이며 전체 작업 시간의 동일한 비율 감소를 의미하지 않습니다.

## 검증

서버·줄 배치 검사 **77개**, 프런트엔드 검사 **49개** 통과. 임시 저장 테스트는 연속 입력 중 내보내기 지연, 유휴 작업 취소, 중복 실행 방지, 오래된 결과 무효화와 즉시 저장을 확인합니다. 정적 파일 테스트는 인코딩 품질값·미지원 인코딩·캐시 분리·조건부 요청·범위 요청·없는 gzip 파일의 원본 제공과 쿠키를 확인합니다.

브라우저에서 기본·전체·집중 보기, 기존 원문 보기 전환, 직접 입력, 유휴 임시 저장과 저장·검증·다운로드를 확인했습니다. 입력 중 내보내기 0회, 입력 중단 후 임시 저장 1회를 관찰했고, 다운로드한 파일을 다시 열어 수정 텍스트·표 보존과 검증 오류 0건을 확인했습니다. 사용자 문서는 벤치마크나 테스트 저장소에 추가하지 않았습니다.

XML·참조 검증, 내보내기 손실 검사, 저장 전후 바이트 확인 및 다운로드 전 검증은 유지했습니다. 복잡한 문서의 편집·조판·명시적 저장 자체는 문서 엔진 처리 시간이 필요하므로 모든 입력 지연이 제거되는 것은 아닙니다.
최신 코드 전반 최적화 기록은 [code-optimization.md](code-optimization.md)를 참고하세요.
