# 백엔드 저장 및 작업 복구

## 업로드와 동시 요청

- 세션의 보관 문서 수 확인과 등록을 SQLite `BEGIN IMMEDIATE` 트랜잭션으로 묶습니다. 19개를 보관한 세션에서 동시에 여러 파일을 올려도 한 파일만 추가됩니다.
- 문서 등록과 최초 분석 작업 등록도 같은 트랜잭션입니다. 작업 등록 실패 시 문서 등록을 취소하고 API가 업로드 디렉터리를 정리합니다.
- 편집 작업에는 DB의 현재 버전과 설정을 기록합니다. 보관 기간이 지난 문서는 새 작업을 등록할 수 없습니다.
- 업로드·편집 파일 저장은 FastAPI의 동기 요청 스레드에서 실행합니다. 비동기 작업 상태 조회도 SQLite 호출을 스레드로 넘겨 이벤트 루프를 막지 않습니다.
- 문서 목록과 문서별 대기 작업 조회에 인덱스를 사용합니다.

## 저장 완료 조건

워커는 프로세스 종료 코드와 결과 JSON 형식을 확인합니다. 결과가 비어 있거나 성공·실패 정보가 함께 있는 응답은 성공으로 처리하지 않습니다.

DB에 버전을 반영하기 직전에 다음을 확인합니다.

1. 해당 작업이 여전히 실행 중인지
2. 문서가 만료되지 않았고 작업의 기준 버전과 현재 버전이 같은지
3. 결과 버전이 분석·검증에서는 현재 버전, 편집에서는 현재 버전 + 1인지
4. 해당 버전의 문서 파일이 존재하고 비어 있지 않은지
5. 스냅샷의 버전·형식·검증 보고서가 작업 결과와 일치하는지

확인 실패 시 작업을 실패로 기록하고 마지막 저장 버전과 검증 상태를 유지합니다. 분석 실패는 문서를 실패 상태로 표시합니다. 이미 완료되거나 재시작으로 중단된 작업의 늦은 완료 통지는 무시합니다.

HWPX 편집 파일·스냅샷·프로세스 결과 JSON은 임시 파일에 작성하고 `flush`/`fsync` 후 교체합니다. 파일 교체가 실패하면 이전 파일을 유지합니다. HWP 편집은 기존의 임시 파일 검증 후 교체 방식을 유지합니다. 파일 두 개와 SQLite를 하나의 파일 시스템 트랜잭션으로 처리하는 것은 아니므로, DB 버전 반영은 두 결과 파일을 확인한 뒤 수행합니다.

## 실패 및 재시작

- 요청 파일 쓰기, 프로세스 시작, 결과 파싱의 오류도 실패 상태로 기록하여 문서가 계속 처리 중으로 남는 경우를 줄입니다.
- DB 완료 기록이 일시적으로 실패하면 같은 문서 작업을 다시 실행하지 않고 실패 상태 기록을 재시도합니다.
- 프로세스 종료 처리나 DB 기록에서 오류가 나도 임시 파일 정리를 실행합니다.
- 재시작 시 실행 중이던 작업은 실패로 기록하고 해당 작업의 요청·결과·편집 후보·임시 파일을 정리합니다. 아직 시작하지 않은 대기 작업과 그 편집 후보는 유지합니다.
- 삭제 중 디렉터리를 `trash-문서ID`로 옮긴 뒤 DB 커밋 전에 서버가 중단되면, 정리 과정에서 남은 문서 행을 확인하고 디렉터리를 복원합니다. DB 삭제가 완료된 파일만 폐기합니다.
- 스냅샷을 읽을 수 없는 경우 API는 503과 복구 안내를 반환합니다. `/api/documents/{id}/original`은 스냅샷 없이 소유권을 확인하므로, 업로드 원본이 남아 있으면 별도로 받을 수 있습니다.

기존의 **단일 호스트·단일 API 프로세스** 실행 조건과 업로드 시점부터 24시간 보관 정책을 유지합니다.

## 회귀 검사

`web_tests/test_backend_reliability.py`는 동시 업로드, 분석 등록 롤백, 불완전한 프로세스 결과, 저장 결과 누락·불일치, 늦은 완료, 파일 교체 실패, 삭제 복원, 재시작 임시 파일 정리, DB 장애 후 재시도, 느린 조회 중 다른 요청 응답을 검사합니다.

`web_tests/test_api.py`에서는 긴 파일명 확장자 보존과 손상·누락된 스냅샷에서 원본 다운로드도 검사합니다. 기존 `web_tests/test_real_roundtrip.py`는 실제 HWP·HWPX 업로드부터 편집·검증·다운로드·재업로드와 개체·첨부 보존을 검사합니다.

```powershell
.\.venv\Scripts\python.exe -m pytest web_tests tests/test_layout_preservation.py -q
```

2026-10-20 확인 결과: 위 회귀 검사 103개 통과. 실행 중인 `127.0.0.1:8000`에서도 생성한 HWPX와 실제 HWP 샘플(`기출킬러양식.hwp`)의 업로드 → 편집 → 검증 → 다운로드를 검사했습니다. 다운로드 파일의 수정 내용을 재열기로 확인했고 새 검증 오류는 0개, 업로드 원본은 바이트 단위로 동일했습니다. 이 검사에서 만든 서버 문서는 검사 후 삭제했습니다.
