# 웹사이트 기본 점검 및 보완

점검일: 2026-10-21. 대상은 기존 로컬 HWP/HWPX 문서 편집기다. 공용 서버 배포나 외부 문서 전송은 진행하지 않았다.

## 확인하고 수정한 항목

| 영역 | 발견한 문제 / 확인 내용 | 보완 |
| --- | --- | --- |
| 통신 복구 | API와 편집기 원본 요청에 요청 자체의 시간 제한이 없었음 | 일반 JSON 요청 30초, 파일 업로드 90초, 원본·예제 파일 60초. 응답 본문 수신까지 제한하고 타이머·취소 이벤트를 정리한다. 호출자가 요청을 취소한 경우 AbortError를 유지한다. |
| 저장 안정성 | 통신 실패·시간 초과 시 처리 여부를 구분하기 어려움 | 한국어 오류 안내를 제공한다. 저장 요청을 자동 재전송하지 않으며 처리 여부를 확인하도록 안내한다. 편집 상태를 자동 초기화하지 않는다. |
| 연결 상태 | 연결 단절 안내와 초기 목록 조회 재시도 수단이 부족함 | 브라우저의 online/offline 상태를 표시하고 문서 목록 다시 확인 버튼을 제공한다. offline 값은 서버 도달 여부의 확정 판정이 아니므로 저장·다운로드를 강제로 차단하지 않는다. |
| 키보드 조작 | 대화상자의 링크 누락, 숨겨진 요소·비활성 컨트롤 포함, 창 밖 초점 이동, 중복 구현 | 새 문서·작업 도구·고급 설정·버전 기록·수정 검토·도움말·검증 결과의 초점 처리를 공통화했다. Tab/Shift+Tab 순환, Escape, 원래 위치 복원, 중첩 창과 스크롤 잠금을 처리한다. 닫기 동작 변경만으로 입력 위치를 초기화하지 않는다. |
| 탐색·초점 | 설정 탭의 방향키 탐색과 본문 건너뛰기 부재 | 설정 탭의 방향키·Home·End와 roving tabindex를 구현했다. 본문 건너뛰기 링크, 입력란 초점 표시, 고대비 모드 초점 표시를 추가했다. 문서명·미저장 상태를 브라우저 제목에 표시한다. 기존 동작 줄이기 설정에 애니메이션 반복 제한을 더했다. |
| 오류 화면 | 전체 React 렌더 오류 시 화면 복구 안내가 없음. 없는 주소는 일반 오류 응답 | 최상위 오류 경계와 명시적 다시 불러오기 버튼, JavaScript 비활성 안내, 초기 로딩 실패 시 다시 열기 링크, 한국어 404 페이지를 추가했다. 임시보관되지 않은 마지막 입력의 손실 가능성도 안내한다. |
| 파일 선택 | 빈 파일은 서버까지 전송한 뒤 실패하고 여러 파일 드롭은 첫 파일만 열었음 | 빈 파일은 즉시 안내하며 여러 파일을 놓으면 한 파일씩 열도록 안내한다. 확장자·20MB 제한은 유지한다. |
| 보관 안내 | 서버 보관본과 브라우저 임시본의 보관 위치·기간이 혼동될 수 있었음 | 서버 전송, 서버의 24시간 보관, 세션 쿠키 접근 구분, 별도로 남을 수 있는 브라우저 임시본, 공용 기기의 사이트 데이터 정리를 도움말에 명시했다. 실제 사용하지 않는 AI 처리 기능은 추가하지 않았다. |
| 응답 보안 | 출처가 다른 변경 요청의 조기 403 응답에는 공통 보안·캐시 헤더가 빠졌음 | 403과 예상치 못한 500에도 보안 정책과 API no-store를 적용했다. 500 응답에는 문서 내용·서버 경로·추적 정보를 포함하지 않는다. 카메라·마이크·위치 권한 제한을 사이트 전체에 적용하고 HTTPS에서는 Secure 세션 쿠키를 사용한다. |
| 캐시·오류 페이지 | HTML 404가 있으면 압축 파일 탐색이 404 HTML을 gzip으로 오인할 수 있음 | 압축 응답은 200/304만 채택하고 실제 파일로 대체한다. 없는 해시 자산에 immutable 캐시를 적용하지 않는다. 기존 ETag·Range·gzip 협상과 해시 자산 장기 캐시는 유지한다. |
| 의존성 | 현재 설치·잠금 상태를 점검 | npm audit 결과 알려진 취약점 0건, pip check 의존성 충돌 없음. Python 취약점 데이터베이스 감사나 침투 테스트 결과를 의미하지 않는다. |

## 검증

- 프런트엔드 전체 테스트 95개 통과. 이후 공통 초점 처리의 계산 중복 제거는 해당 초점·UI 테스트 10개를 다시 실행해 통과했다.
- 백엔드 전체 테스트 107개 통과. 기존 실제 HWP/HWPX 업로드 → 편집 → 검증 → 다운로드 → 재열기 검사를 포함한다.
- 404 처리 변경 이후 정적 파일·기본 사이트 테스트 21개를 별도로 재검증해 통과했다.
- TypeScript 검사와 배포 빌드 성공. 초기 메인 JS는 338.60KB, gzip 101.83KB이며 기존 지연 로딩을 유지한다.
- 실행 기록은 로컬 비추적 경로 `build/validation/website-*-tests.log`, `build/validation/website-audit-dependencies.json`에 보관한다.

자동 테스트는 React/jsdom 및 FastAPI TestClient를 사용한다. 실제 브라우저 도구는 기존 접근 제한으로 이용하지 않았으므로 실제 모바일 화면, 스크린리더, 모바일 한글 입력, 200% 확대의 육안 검사를 완료했다고 주장하지 않는다. 접근성 전체 적합성 인증도 아니다.

## 공개 배포 전에 별도로 확인할 운영 항목

- 도메인·HTTPS·역방향 프록시의 신뢰 범위와 Secure 쿠키 전달을 실제 배포 환경에서 확인한다. 현재 기본 실행은 127.0.0.1 전용이다.
- 파일 저장 디렉터리를 정적 서버 경로 밖에 두고 운영체제 접근 권한, 디스크 용량, 작업 실패·만료 정리 모니터링을 확인한다.
- 이 서비스의 세션 쿠키는 브라우저별 문서 접근을 구분한다. 계정 로그인·조직 권한·기기 간 동기화를 제공하는 기능은 아니다.
- 실제 기기에서 작은 화면·화면 확대·키보드·스크린리더·IME·새로고침·다중 탭 충돌·느린 네트워크를 확인한다.
- 서비스 운영 주체, 공개 도메인, 실제 보관 방식에 맞춘 개인정보·문의 안내는 운영 정보가 정해진 뒤 확정한다.
