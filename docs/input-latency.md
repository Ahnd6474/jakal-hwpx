# 입력 지연 개선

## 확인한 병목

표와 수식이 많은 문서에서 Canvas 글꼴을 지정할 때마다 같은 CSS 글꼴 체인의 파싱·치환·중복 제거를 반복했습니다. 문서의 글자 변경보다 페이지를 다시 그리는 시간이 길었습니다.

문서의 국소 편집 경로는 이미 프레임 단위로 화면을 갱신했지만, 전체 화면 갱신이 필요한 편집은 `document-changed`마다 즉시 다시 그렸습니다. 연속 입력이 들어오면 같은 화면을 반복 계산했습니다. 문서 로딩 중 글꼴 완료 알림도 불필요한 전체 갱신을 발생시킬 수 있었습니다.

앱의 HWPX 임시 보관과 편집기 내부의 HWP 임시 보관이 중복 실행됐습니다. 앱의 임시 보관도 긴 IME 조합 중 입력이 잠시 멈추면 내보내기를 시작할 수 있었습니다.

## 변경

- **그리기 작업 안에서만 글꼴 해석을 재사용합니다.** 최대 1,024개를 보관하고 작업이 끝나면 폐기합니다. 다른 문서의 글꼴 범위와 중첩된 작업은 구분합니다. 새 그리기에서는 새 글꼴 상태를 확인하므로 설치·로딩·치환 변경을 오래된 캐시로 덮지 않습니다.
- **전체 갱신 요청도 프레임당 한 번으로 모읍니다.** 글자 변경과 실행 취소 기록은 즉시 처리하며 마지막 문서 상태를 그립니다. 문서 교체·초기화 시 대기 작업을 취소하고, 다른 문서 세대의 요청은 무시합니다. 자동화 API의 엄격한 렌더 완료 경로는 유지합니다.
- **문서 로딩 중 글꼴 완료에 따른 재갱신을 생략합니다.** 글꼴을 준비한 뒤 최초 페이지를 그리는 기존 초기화 순서를 사용합니다. 새 파일을 파싱하기 전에 이전 입력 핸들러를 비활성화합니다. 임시본 복원 중에도 로딩 화면과 입력 잠금을 표시합니다.
- **임시 저장의 담당을 앱으로 통일합니다.** embed 모드의 편집기 내부 HWP 자동 저장은 끄고 기존 앱의 버전별 HWPX 임시 보관은 유지합니다. Studio를 단독으로 열면 내부 자동 저장 정책을 유지합니다.
- **IME 조합 중에는 임시 내보내기를 시작하지 않습니다.** 조합이 끝난 뒤 2.5초의 입력 휴지기를 다시 기다립니다. 탭을 배경으로 보내는 경우에도 조합 중에는 강제로 내보내지 않습니다. 명시적 저장·검증·다운로드의 검사는 유지합니다.

고정 Studio 소스는 수정하지 않고 `web/scripts/build-studio.mjs`에서 빌드 통합을 적용합니다. 대상 코드가 달라지면 빌드를 중단하며, 통합 파일 해시가 바뀌면 Studio를 다시 빌드합니다.

## 측정

동일한 로컬 브라우저·Canvas2D·117% 배율에서 `math_template_2_formula_fixed.hwpx` 원본을 사용했습니다. 20쪽, 본문 표 16개, 수식 522개인 문서입니다. 같은 위치에 `LatencyCheck12345`를 17개 키 입력으로 넣고 글꼴 캐시 적용 전후를 비교했습니다. 비교 전 원본 파일을 바이트 단위로 동일하게 복원했습니다.

| 항목 | 적용 전 | 글꼴 캐시 적용 후 |
|---|---:|---:|
| 입력 후 다음 화면 경계까지 중앙값 | 81.0ms | 36.5ms |
| 페이지 갱신 평균 | 62.9ms | 15.6ms |
| 측정 입력 중 최대 화면 경계 대기 | 116.6ms | 76.9ms |

페이지 갱신 평균은 약 75%, 입력 대기 중앙값은 약 55% 감소했습니다. 이는 해당 샘플의 비교 결과이며 모든 문서에 같은 비율을 보장하지 않습니다. 화면 경계 시간은 입력 이벤트부터 두 번의 `requestAnimationFrame` 경계를 통과할 때까지의 근사값으로, 화면 장치 자체의 표시 지연을 측정한 값은 아닙니다.

저장본을 다시 연 후 전체 갱신이 발생하는 경로에서도 10자 연속 입력을 확인했습니다. 적용 전 10회였던 `refreshPages` 호출이 프레임 병합 후 2회로 줄었으며, 최종 입력을 저장·검증·다운로드하고 다시 열어 누락이 없음을 확인했습니다. 이 후속 실행에서는 화면 경계 기록이 1초 이상으로 나타나 앞의 지연 수치와 합산하지 않았습니다. 전체 갱신 자체도 여전히 최대 약 110ms가 걸렸으므로 복잡한 문서의 모든 입력을 37ms 이내에 처리한다는 의미는 아닙니다. 원시 측정값은 로컬 `build/validation/web/input-latency-*.json`에 보관했습니다.

로컬 진단은 `?profile-input=1`에서만 활성화하며 DOM 속성에 시간·횟수만 기록합니다. 입력한 글자나 문서 본문을 기록하거나 외부로 보내지 않습니다. 일반 사용에서는 측정 래퍼와 입력 진단 리스너를 설치하지 않습니다.

## 검증

프런트엔드 검사 65개 통과. 글꼴 캐시의 작업별 수명·범위 분리·오류 복구·상한, 전체 화면 갱신 병합·취소, 긴 IME 조합·대기 중 조합 시작·즉시 저장을 검사했습니다. Studio 저장·인라인 줄 배치 서버 검사 11개도 통과했습니다.

브라우저에서 실제 수식 문서에 영문·한글·이모지를 입력하고 저장·검증·다운로드했습니다. 다운로드 파일을 다시 열어 입력 텍스트와 검증 오류 0건을 확인했습니다. 마스터 페이지를 포함한 표 20개·수식 522개·그림 9개, 병합 셀 구조와 첨부 파일 바이트도 유지됐습니다. OS IME의 실제 조합 키 입력 자체는 자동화로 재현하지 않았으며 조합 이벤트에 따른 임시 저장 제어는 회귀 테스트로 확인했습니다.
