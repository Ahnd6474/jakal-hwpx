# 코드 전반 최적화

범용 문서 편집 동작과 원문 보존을 유지하면서 반복 연산·메모리 할당·초기 다운로드·숨겨진 화면의 작업을 줄였습니다.

## 변경 범위

### 서버 문서 엔진

- 문단마다, 텍스트 노드마다 반복하던 XPath 컴파일을 재사용합니다. 가장 가까운 문단이 일치하는 텍스트만 가져오며 표·각주 등 안쪽 문단은 제외합니다. 인라인 줄바꿈·탭·공백·꼬리 텍스트는 유지합니다.
- XML 요소마다 QName을 생성하던 개체 보존 검사는 태그를 먼저 집계하고 태그 종류별로 줄 배치 캐시를 제외합니다. 모든 XML 요소·첨부 해시를 비교하는 기존 결과를 유지합니다.
- 문서를 변경하지 않는 분석/검증은 불필요한 중간 서명 생성을 생략합니다. 편집의 중간 검사는 개체 수만 비교하고 첨부 해시를 중복 계산하지 않습니다. 모든 작업에서 원본과 다시 연 결과의 개체·첨부 보존 검사는 계속 수행합니다.
- 첨부 파일을 한꺼번에 읽어 버리던 사전 검사를 1MiB 청크 읽기로 바꿨습니다. 모든 ZIP 멤버를 끝까지 읽어 CRC 오류를 계속 검사합니다. XML은 안전한 파서로 스트림에서 읽으며 DTD·외부 엔티티·파일/압축 해제 크기 제한을 유지합니다.
- 큰 표의 한도는 셀 텍스트 목록을 만들기 전에 확인합니다.

### 프런트엔드

- 원문 뷰어·고급 설정·버전 기록·수정 검토를 필요할 때 로드합니다. 추가 청크 오류는 열린 편집기를 유지하는 기존 오류 경계에서 처리합니다.
- 임시보관은 변경된 항목만 직렬화합니다. 본문/셀 원문 주소 색인은 변경하지 않는 `sections` 배열을 키로 약한 참조 캐시에 보관합니다. 설정·상태 변경에서는 재사용하고 새 문서 내용에서는 교체합니다. 빈 수정 목록은 원문을 탐색하지 않습니다. 원문 순서·표 셀 주소·읽기 전용 처리·빈 문자열 수정·원문 충돌 판정은 유지합니다.
- 검색 필터를 메모하고 문단 목록의 포함 여부는 Set으로 조회합니다. 고급 설정의 규칙 편집 중에는 찾기·바꾸기 미리보기를 다시 계산하지 않습니다.
- 원문 SVG의 불필요한 React 재렌더링을 줄입니다. Worker의 SVG 캐시 조회는 최근 사용 순서를 갱신합니다.

### 뷰어 백그라운드 작업

- 검색 색인 결과를 최대 8쪽/100,000자 단위로 전달합니다. 마지막 부분과 중단 시점의 결과도 전달합니다.
- 원문 뷰어 또는 브라우저 탭을 숨기면 검색 색인이 신호를 기다리며 쉽니다. 화면에 필요한 페이지 요청은 별도로 처리합니다. 전체 검색 한도를 소진하면 저장할 수 없는 검색 텍스트를 얻으려고 추가 페이지를 렌더링하지 않습니다.
- 같은 문서의 뷰어를 숨길 때는 Worker와 위치를 유지합니다. 숨겨진 동안 저장 버전이 바뀌면 이전 Worker를 해제하고 다시 보일 때 최신 파일을 엽니다. 이전 Worker의 늦은 결과/오류는 새 화면에 적용하지 않습니다.

## 측정

| 항목 | 적용 전 | 적용 후 |
|---|---:|---:|
| 20쪽 샘플의 문서 정보 생성 중앙값 | 104.68ms | 16.88ms |
| 같은 샘플의 개체·첨부 서명 생성 중앙값 | 19.56ms | 8.98ms |
| 같은 샘플의 ZIP 사전 검사 중앙값 | 33.48ms | 34.04ms |
| 12MiB 첨부 사전 검사의 Python 추적 할당 최대치 | 12,599,829B | 1,064,671B |
| 2만 문단/1항목 변경 임시보관 중앙값 | 16.15ms | 약 0.06ms |
| 초기 메인 JavaScript, 압축 전 | 약 415KB | 약 334KB |
| 초기 메인 JavaScript, gzip | 약 128KB | 약 100KB |
| 500쪽 색인 결과의 메시지 수 | 500 | 63 |

서버는 `math_template_2_formula_fixed.hwpx`를 같은 프로세스에서 이전 코드와 새 코드로 번갈아 11회 실행했습니다. 문서 정보와 서명 값의 동일성을 확인했습니다. 첨부 메모리는 tracemalloc이 추적한 Python 할당이며 전체 프로세스 RSS가 아닙니다. ZIP 검사는 속도 개선보다 메모리 감소가 목적입니다.

임시보관은 메모리 저장소 대역으로 측정한 색인/직렬화 비용이며 실제 브라우저 저장소의 I/O 시간은 포함하지 않습니다. 최초 변경 시 색인 생성은 약 31ms였고 약한 참조 캐시를 재사용하는 후속 처리의 중앙값이 약 0.06ms입니다. 원문 배열을 직접 수정하지 않는 기존 React 상태 관리가 전제입니다.

JavaScript 크기는 이번 작업 직전과 이후의 프로덕션 빌드 비교입니다. 추가 도구를 열면 해당 청크를 내려받으므로 전체 기능 코드의 삭제를 의미하지 않습니다. 시간은 해당 샘플의 결과이며 실제 키 입력→화면 표시 지연이나 모든 문서의 같은 개선 비율을 보장하지 않습니다.

## 검증

- 프런트엔드 전체 83개 통과. 임시보관의 빈 목록/희소 수정/주소/순서/캐시 교체, 색인 배치/중단/재개, 독립 컴포넌트의 뷰어 숨김/버전 교체/늦은 응답 폐기를 포함합니다.
- 서버 전체 97개 통과. 이후 최종 변경에 대해 실제 HWP/HWPX 업로드·편집·검증·다운로드·재열기, 인라인 줄 배치, 중첩 문단 추출과 큰 첨부 CRC 검사를 포함한 관련 12개도 통과했습니다.
- TypeScript 및 프로덕션 빌드 통과. 원시 결과는 로컬 `build/validation/optimization/`에 보관했습니다.
- 브라우저 도구의 앞선 로컬 접근 차단은 유지되어 실제 브라우저 화면·키 입력 측정은 수행하지 않았습니다. Worker/React 동작 검사는 실사이트에 접근하지 않는 독립 테스트입니다.
